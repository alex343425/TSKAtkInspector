# 戰鬥 ATK／爆擊傷害／敵方 DEBUFF 明細

《ティンクルスターナイツ》用的非官方 BepInEx 6 IL2CPP 插件，搭配 [TSKHook](https://github.com/TSKModding/TSKHook) 使用。

戰鬥待機操作介面會在目前角色的 ATK 上方顯示 `Cri 80% CriDmg 200%` 格式的遊戲當前爆擊率與可檢測爆擊傷害倍率；角色切換、爆擊率／爆傷 BUFF 與 RUSH 數變化時每 0.25 秒更新。

敵我雙方最多十個時間軸角色圖示會常態顯示距離行動線的完整 CT。遊戲原本只在超過畫面端 22 CT 時顯示超出量；插件改為直接顯示 `時間軸位置＋STUN 待機 CT`，因此原顯示 2 時會顯示 24，距離小於等於 22 CT 時也不隱藏。

每個存活的敵方時間軸圖示會常態顯示兩行倍率：上行是共通被傷增減倍率 E，下行是命名 DEBUFF 倍率 F。F 依右側目前待機角色的屬性、種族與攻擊類型即時判斷；目前角色切換後會在 0.25 秒內更新。敵人的時間軸位置達到 16 CT 以上時顯示在圖示下方，小於 16 CT 時顯示在圖示上方；此版面切換門檻不計 STUN 額外待機 CT。

## 使用

1. 關閉遊戲，再從平常使用的 DMM 入口啟動。
2. 進入戰鬥，右側角色操作介面的 ATK 上方會顯示目前 `Cri`／`CriDmg`；點選 ATK 數字或其左側的 ATK 標籤可開啟明細。
3. 也可以用 **F9** 開關明細。滑鼠滾輪捲動，點「關閉」或視窗外的暗色區域關閉。
4. 用視窗下方的「ATK 明細」、「爆擊傷害明細」與「敵方 DEBUFF」切換分類。敵方頁可用上方「敵 1」～「敵 5」切換存在的目標。
5. 「顯示全部效果／原始參數」可查看目前分類以外的效果，方便確認特殊技能。
6. 「儲存明細」會覆寫遊戲目錄內的 `BepInEx/AtkInspector-last.txt`。

視窗每 0.25 秒讀取一次最新資料。開窗時固定查看該角色，自動戰鬥換人後仍查看原角色；關閉後重新點 ATK 即可換人。

效果清單採緊湊排版：第一行合併效果名稱、有效量與期限，第二行顯示來源；一般效果之間不留空白行，以便同頁顯示更多項目。

**開窗不會暫停戰鬥。** 需要靜止查看時，可使用既有暫停操作或 TSKHook 的 F5；F6 恢復正常速度。插件不調整遊戲速度。

## 顯示內容

- 進場初始化時記錄的角色基礎 ATK，以及目前經場地／形態修正後的計算基礎。
- 與遊戲 ATK 文字相同的 `GetAttack(false)` 當前值。
- 遊戲認定的各筆 ATK BUFF、當前有效百分比、ATK DEBUFF；重複 BUFF 逐筆保留。
- 每筆效果的剩餘／最大 CT、自身行動、對象行動、蓄力選擇或發動次數。
- 可識別的施放角色與技能名稱／等級。技能名稱以效果 ID 對照，多個相符結果會明確標示。
- 蓄力、超蓄力、參照施放者 ATK 的加算、形態變化，以及適用於該角色的 ATK 場地修正。
- ATK BUFF 強化、複製效果等狀態標記；其他特殊效果提供原始參數。
- 爆擊傷害倍率的原生基礎 150%、目前效果清單加成、可檢測倍率與目前 RUSH。
- 各筆 `CriticalDamageUp*` 與シスター爆傷效果的有效量、期限、來源及條件；爆擊率 `CrtUp`、STUN 傷害與屬性克制傷害不混入此分類。
- `SisterCriticalDamageUpRush` 依遊戲原生公式，以基礎值＋每 RUSH 增量計算並套用上限。
- 敵方 1～5 號目標各自的被傷增減倍率 E：`100%＋DmgUp－DamageDown`，並逐筆顯示有效量、期限與來源。
- 各敵方目標的命名 DEBUFF 倍率 F。標的、融解、極冷、帶電、聖痕、審判、裂傷、破碎、魔障、崩壞等會依開窗時固定的我方角色判斷是否適用。
- 頁首同時顯示 E、F 與只合併這兩區的 E×F；`DamageCut` 維持標示為不同乘區。

來源是在效果實際套用時記錄。シスター會顯示為「シスター：角色 ／ アクティブスキル」或「シスター：角色 ／ チームスキル」，兩個裝備中的シスター會分開辨識。效果 ID 會被大量不同技能共用，因此不再只靠效果 ID 對照；若插件沒有見到套用事件，僅在完整參數唯一相符時列為候選來源。

## 資料範圍

入場角色資料已合併養成、裝備等戰前因素，插件不能憑空拆出遊戲沒有提供的細項。未捕捉入場時，不會把後來觀察到的 ATK 冒充入場快照。

一般 ATK BUFF 使用遊戲已計算的 `SkillEffectValue`，不是直接把技能設定的第一個參數當有效加成。部分特殊／間接效果保留原始參數，標為「未換算」。被動技能尚未觸發且未加入目前效果清單時，不列為正在生效的 BUFF。

爆擊傷害頁的倍率只在攻擊判定為爆擊時使用。它顯示目前效果清單可檢測的倍率；傷害結算另有依當次技能與目標傳入的單次爆傷值，因此未選定攻擊前不併入頁首合計。

敵方頁的 F 取決於攻擊者屬性、種族與攻擊類型，因此以開窗當下固定的我方角色作為條件判定者。敵方條件被動減傷若還要依普通攻擊、蓄力、UNISON／RUMBLE 或 EX 判定，會另外提示而不提前混入共通 E。`DamageCut` 不會與被傷增加相消，所以不列入 E 或 F。

`Time` 是剩餘量，`TimeMax` 是最大量，`Duration` 是已經過量。插件不使用真實秒數估算 CT，也不將未知負值或 0 猜成永久效果。場地效果沒有個別倒數欄位時會直接說明。

遊戲會把部分效果合併後取整，並對 ATK 百分比減益套用 -80% 下限。蓄力、參照施放者 ATK、特殊被動等分開計算，所以各列不是可以直接相乘的最終傷害倍率；目前 ATK 以遊戲原生計算為準。

## 安裝與移除

從 GitHub Releases 下載最新版壓縮檔，關閉遊戲後將其中的 `BepInEx` 資料夾解壓到遊戲根目錄。完成後應存在 `BepInEx/plugins/TSKAtkInspector.dll`。

移除時先關閉遊戲，再將這一個 DLL 移出 `BepInEx/plugins`。不必修改或移除 `TSKHook.dll`、其設定或遊戲主程式。

## 編譯與檢查

需要 .NET 8 SDK、目前遊戲的 `BepInEx/core` 與 `BepInEx/interop`，以及本機快取中的 .NET 6.0.36 targeting packs。本環境已具備，`NuGet.Config` 停用遠端套件來源。

請將倉庫放在遊戲根目錄的 `mods/AtkInspector`，讓專案與腳本使用的相對路徑能找到遊戲組件。遊戲 DLL、interop 產物與反組譯輸出不包含在倉庫內。

```powershell
.\mods\AtkInspector\build.ps1
.\mods\AtkInspector\test.ps1
.\mods\AtkInspector\build.ps1 -Install
```

`-Install` 如遇已存在的本插件，先備份到 `mods/AtkInspector/backups`。測試會檢查時間單位、百分比、未知期限處理、Harmony 目標，以及產物只呼叫遊戲讀取介面。

## 驗證狀態

已完成 Release 編譯與離線檢查。**シスター來源追蹤仍需重新啟動遊戲後驗證**；執行中的舊版插件不會熱更新。

第一次實測建議確認：

1. `BepInEx/LogOutput.log` 有 `TSK ATK Inspector` 的 loaded 訊息，進入角色操作介面時有 `ATK click target attached`。
2. 點 ATK 或按 F9 能開窗；數值等於右側 ATK；關閉／捲動不會觸發底下技能按鈕。
   ATK 上方應同時顯示如 `Cri 80% CriDmg 200%`；套用爆擊率／爆傷 BUFF 或更換目前角色後，數值應在 0.25 秒內更新。
3. 套用兩筆 ATK BUFF 後出現兩列；走過 CT 後剩餘量減少；到期／解除後消失。
   シスター「アポロ」的常駐 `AtkUpTypeOut` 應顯示「シスター：アポロ ／ チームスキル · シャドウムーン Lv.10」，不應再列出フィオナ的多個技能。
4. 切換「爆擊傷害明細」後，確認基礎為 150%；套用 `クリティカルダメージ倍率UP` 後逐筆顯示有效量、剩餘期限與正確來源。若有シスター RUSH 型效果，增加 RUSH 時有效量應即時更新並停在上限。
5. 切換「敵方 DEBUFF」與敵 1～5，確認每個存在目標的 E／F、效果、期限與來源獨立顯示；融解等條件效果會隨固定攻擊者判斷是否計入 F。
6. 更換角色、重新挑戰或下一場戰鬥後，角色與入場數值沒有沿用上一場資料。
7. 敵我雙方的時間軸圖示右上角皆應顯示完整 CT；場內 18 CT 顯示 18，原本場外超出量 2 改顯示 24。
8. 每個存活敵方圖示應顯示 E／F 兩行；更換目前待機角色時，具屬性／種族／攻擊類型條件的 F 應同步改變。敵人的時間軸位置達到 16 CT 以上時，標籤應切換到圖示下方；STUN 額外待機 CT 不應提早觸發切換。
9. 若顯示不符，使用「儲存明細」並保留 `LogOutput.log`，可據此修正。
